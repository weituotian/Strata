## 4. 已解决的独立问题（**别再和掉电混为一谈**）

### 4.1 PCIe 宽度掉到 x4（已修，但不影响掉电）

- **现象**：`nvidia-smi` 报 `Link Width Current 4x / Max 16x`（代际不变），引擎自测 host→device 从 **26.8 GB/s 掉到 6.6 GB/s**，`pcie_frac` 自适应 0.55 → 0.18。
- **定位过程**：先疑 M.2 通道共享 → 被拓扑否掉（GPU 在根端口 `00:01.1`、两块 M.2 在 `00:01.2` 与 `00:02.1`，**各自独立、中间无交换机**）；再疑 BIOS → 被时间线否掉。
- **根因**：**SlimSAS 外接链路的触点/线**。**重新插拔后立刻回到 x16**（26.7 GB/s / `pcie_frac 0.55`），持续 249 秒采样全部 `width 16`。
- **为什么"没人碰过它"也会变**：高密度连接器会因热循环/氧化/微裂自己退化；而没训练上来的通道**不产生任何错误事件**，所以表现为"宽度悄悄变小、零 AER/WHEA"。
- ⚠ **教训**：这条假设曾经看起来能同时解释"x4"和"无痕硬复位"，很诱人 —— **但 10/15 的硬复位把它证伪了**。不要因为它"故事好听"就保留。

### 4.2 模型数据 `G:` → `D:` 搬迁（已完成）

- 5 个配置文件、共 **25 处**路径（含顶层 `tokenizer` 字段，最容易漏），已全部改完；路径存在性校验 **TOTAL MISSING: 0**。
- 服务实测从 `D:\models\strata_data` 加载成功（`experts loaded: 46.84 GiB`）。
- **不需要改**：环境变量（无）、启动脚本（全走 `--config`）、`setup.py`/`serve/`、`cfg-backup\`（那是校验基准，故意保留旧值）。

### 4.3 `tools/strata_bench.py` 编码 bug（已修）

- `project_version()` 读 `CMakeLists.txt` 时未指定编码 ⇒ 中文 Windows（默认 gbk）解码 UTF-8 BOM 直接抛 `UnicodeDecodeError`，**整个 benchmark 在第一步就崩**。
- 已加 `encoding="utf-8", errors="replace"`（**本仓库唯一的代码改动**）。Linux 默认 UTF-8 不触发；**从上游重拉代码后会被还原，记得再补**。

## 5. ✅ 掉电根因（已确认）：电源 PSU

### 5.1 结论

| 项 | 内容 |
|---|---|
| **根因** | **电源（PSU）** —— 供电瞬态（load transient）引发**平台级瞬时复位** |
| 怎么确认的 | 另一台 **Ubuntu** 机器上的一段**瞬态负载脚本**能**稳定复现**同样的硬复位（脚本在那台机器上，本机暂时访问不到 —— 见 §5.3） |
| 怎么修好的 | **仅更换电源**，其他一概未动 |
| 与现场吻合度 | ✅ 完全吻合：`BugcheckCode = 0` + 无 WHEA + 无 dump + 无电源键 ⇒ 平台在 OS 能记录之前就被复位；黑匣子死前 1 秒毫无异常（因为根本不是软件层的事） |

### 5.2 复盘：真正指向它的两条硬证据，当时就在手上

1. **10/16 21:46 那次硬复位时，Strata 根本没在跑** —— 这一条应当直接把"引擎 / 请求路径 / 内存分配"整族假设**全部打掉**，把结论钉到硬件层。
2. **掉电瞬间 GPU 只有 32–168 W、51–65 °C，且有一次是纯 idle** —— 它排除了"稳态功耗 / 温度 / 满载"，但**对瞬态 `dI/dt` 毫无排除力**。
   当时把 `avx512_stress`（2346 GFLOP/s）和 GPU DMA/GEMM/graph 压力的"存活"当成反证，是**误用**：那些只证明**单向**压力安全，**没有**证明 **CPU + GPU + PCIe 同时突变**安全。

**我排错在哪**：旧版 `§5.1` 把 **H3（提交上限 / 页面文件）排在第一位**，依据只是"死前一刻 `commit 91.00 / 100.72 GB`"这一个**相关**数字，却把它当成了强证据。**正确排序应当是 H2（供电瞬态）第一。**
⇒ 与 §4.1 同一条教训：**相关性不能顶替机制；像 `BugcheckCode = 0` 这种"机制级"证据，应当压过任何单个漂亮的相关性。**

### 5.3 以后怎么验收

- **最方便的验收**：跑 **BENCH 全套**。旧电源下它**必然**在"模型就绪后约 4 分钟、第 3 条左右的请求"处硬复位（10/14 17:55 与 10/15 02:38 两次都是）。**换电源后同一套 BENCH 应当能完整跑完。**
- **更可控的验收**：把另一台 Ubuntu 上那段**瞬态脚本**拿过来跑。⚠ **建议尽快把它复制到本机（或放进 `D:\strata-blackbox\`）留档** —— 否则以后换电源、加 UPS、加电容时就没有对照工具了。
- 记录方式不变：起服务前/后按 §7 记 PCIe 宽度与自测带宽，跑测试时让黑匣子开着。

### 5.4 当时的观测（保留，供以后对比）

- **死点分布**：请求期、读 prompt 期、纯 idle 期**都死过**；两次 BENCH 都死在"就绪后约 4 分钟、第 3 条请求"。
- **黑匣子死前 1 秒毫无异常**（无功率尖峰、无温度异常、无 commit 突增的可见前兆）—— 正是"平台级瞬态复位"该有的样子。
- ⚠ 无法从 trace 判断死点：`verify window` 占全部 trace 行的 **88%**，任何随机时刻死亡都有 88% 概率落在那里。**"死在 verify window"零信息量。**

### 5.5 ⚠ 时钟不可靠（会污染时间线）

系统时钟在不同启动之间会跳（曾快约 35 分钟），事件日志里存在**时间戳比当前 boot 还"新"**的旧事件。
⇒ **跨重启的绝对时间不能直接排序**。判断先后请用：**文件追加顺序 + uptime + 相对顺序**三者对齐。

## 7. 每次测试必须记录的三件事（**别再漏**）

```powershell
# 1) 链路宽度与代际（速度对比的前提）
nvidia-smi --query-gpu=index,name,pcie.link.gen.current,pcie.link.width.current,pcie.link.width.max --format=csv

# 2) 引擎自己探测的 host->device 带宽（写进引擎日志，免费）
Select-String -Path <STRATA_DIR>\strata-iq3_s.log -Pattern 'PCIe probe' | Select-Object -Last 1
#    x16 ⇒ 约 26.8 GB/s / pcie_frac 0.55      x8 ⇒ 约 13 GB/s      x4 ⇒ 6.6 GB/s / 0.18
```

- **两台/两次的 `PCIe probe` 值不一致时，tok/s 的差异就不是 OS/版本的功劳，整组对比作废。**
- 现在 3090 是 **×8**，所以它的基线是 **~13 GB/s**，不再是 26.8。
- `bench.sh` / `BENCH.bat` **不带参数会按 mtime 取最新的 `strata-*.json`** —— 本机有好几个配置，会选错模型和端口（曾在 8080 另起一个模型抢显存）。**永远显式传 `--config`。**

### 10.4 ⚠ 方法学：串行跑臂会漂，必须交错

同一场测试里，短问答解码随**时间顺序**从 **91.7 漂到 79.5（−13%）**，其间 GPU 采样为 **1965/2130 MHz、61 °C、217 W** ⇒ **不是降频、不是功耗墙**。

- **prompt 类指标稳定**（同一配置 4 次运行跨度 ≤ ±1.5%）→ **可以下结论**
- **短问答 / agent 解码有 ±7~13% 漂移** → **不能跨臂比**
- ⇒ 比参数必须 **A/B/A/B 交错**。本轮若只看第一轮，会把 `--mtp-hnorm` 误判成 **+7.3% 的赢家**。

2. **它会把结果写回配置文件**（即使结论是"不用改"也会重排 args）。改前备份：`D:\strata-blackbox\cfg-20261017-pre-calibrate\`

**结论行：`tuned for this PC: the default settings are already the fastest here (98.3 tok/s)`** —— `settings = {}`，一个都没改。但四项扫描本身有信息量（采纳门槛 = 比默认快 **>3%**）：

| 设置 | 三轮中位 | 最好 vs 默认 | 采纳 |
|---|---|---|---|
| `--pcie-frac` | 0: **96.9** ｜ 0.2: 100.7 ｜ 0.35: 100.6 ｜ 0.37(默认): 98.7 ｜ 0.55: 99.6 ｜ 0.75: 100.3 ｜ 0.9: 98.4 ｜ 1.0: 97.4 | +2.0% | ❌（**0.00 最差**） |

### 11.6 性能与取舍

- **首次编码约 30 s**（CPU、1024 图像 token、8 线程）。**同一张图再发命中缓存**（按图片内容哈希），不重复编码。
- `threads` 从 8 调到 16 大约快一倍（7940HX 有 32 线程，但引擎的解码也吃 CPU）。
- 本机 CPU 有 AVX-512，编码器会**自动关闭 flash attention**（源码注释：AVX-512 上开 FA 反而慢约 3 倍）—— 这是正确行为，别手动 `--flash-attn on`。
- 想更快：`"gpu": true` + 重建时 `-DSTRATA_VISION_CUDA=ON`，代价是占 ~1 GB 显存并与引擎抢卡（源码注释：server 会先起编码器、再让引擎按剩余显存定专家缓存）。
